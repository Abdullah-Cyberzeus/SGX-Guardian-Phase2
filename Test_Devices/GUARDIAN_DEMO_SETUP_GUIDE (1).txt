GUARDIAN DEMO ENVIRONMENT SETUP GUIDE

COMPLETE FILES INCLUDED:

1. modbus_plc_simulator.py (580 lines)
   - Python-based Modbus TCP PLC simulator
   - 4 virtual industrial PLCs (injection molding, conveyor, quality)
   - Realistic behavior simulation (setpoints, sensor values, state management)
   - Programmable anomaly injection (invalid commands, supply chain implants)
   - Threading-based simulation loop

2. Dockerfile.modbus
   - Container definition for Modbus PLC simulator
   - Python 3.11-slim base
   - Exposes ports 5020-5023 for 4 PLC instances

3. docker-compose-guardian-demo.yml
   - Orchestration file for Guardian + Modbus Simulator
   - Guardian SG-X service (web UI on 8443, API on 5000)
   - Modbus Simulator service (PLCs on 5020-5023)
   - Shared Docker network for communication
   - Health checks and volume management

4. demo_scenario_controller.py (350 lines)
   - Interactive scenario selection and execution
   - 5 pre-built demo scenarios:
     a) Normal Operation (baseline)
     b) Single Device Anomaly Detection
     c) Multi-Device Cascade Attack
     d) Supply Chain Implant Detection
     e) Insider Threat - Unauthorized Command
   - Realistic timing and event sequences
   - Output logging for presentation

5. README_GUARDIAN_DEMO.md (comprehensive guide)
   - Architecture overview
   - Getting started (quick start in 5 steps)
   - Virtual PLC specifications
   - Detailed scenario descriptions
   - Guardian monitoring procedures
   - Demo workflow for presentations
   - Troubleshooting guide

================================================================================
QUICK START (5 MINUTES)
================================================================================

Prerequisites:
- Docker & Docker Compose installed
- 2GB+ disk space
- Ports 8443, 5000, 5020-5023 available

Steps:

1. Copy all files to a directory:
   mkdir ~/guardian-demo
   cp * ~/guardian-demo/
   cd ~/guardian-demo

2. Start containers:
   docker-compose -f docker-compose-guardian-demo.yml up -d

3. Verify containers running:
   docker-compose -f docker-compose-guardian-demo.yml ps

4. Open Guardian Web UI:
   https://localhost:8443

5. Run a demo scenario:
   docker exec modbus_plc_simulator python3 demo_scenario_controller.py
   (Select scenario 1-5 or 6 to run all)

================================================================================
DEMO SCENARIOS (5 TOTAL)
================================================================================

Scenario 1: Normal Operation (60 sec)
  - Baseline behavior, all PLCs operating normally
  - Shows Guardian passive monitoring capability

Scenario 2: Single Device Anomaly (45 sec)
  - Unauthorized setpoint change on PLC 1
  - Guardian detects, validates via Byzantine consensus, quarantines <3 sec
  - Key: Autonomous response without SOC triage

Scenario 3: Multi-Device Cascade Attack (60 sec)
  - Coordinated attack across PLC 3 (conveyor) and PLC 4 (quality)
  - Guardian detects pattern, isolates both, preserves uncompromised devices
  - Key: Cross-device threat correlation

Scenario 4: Supply Chain Implant Detection (50 sec)
  - New equipment (compromised during manufacturing) attempts enrollment
  - Guardian validates TPM 2.0 attestation, detects tampering, denies enrollment
  - Key: Hardware-rooted trust prevents implants at root

Scenario 5: Insider Threat (55 sec)
  - Trusted operator with legitimate access attempts invalid command
  - Guardian blocks command via Byzantine consensus despite trusted source
  - Key: Device-layer policy overrides trusted credentials

================================================================================
TROUBLESHOOTING
================================================================================

Containers won't start:
  docker-compose -f docker-compose-guardian-demo.yml logs
  Check ports: lsof -i :8443, lsof -i :5020-5023

Guardian not discovering PLCs:
  docker exec guardian_sg_x nc -zv modbus_plc_simulator 5020
  docker logs modbus_plc_simulator | tail -20

Anomalies not triggering:
  docker logs modbus_plc_simulator | grep ANOMALY
  Check scenario controller output

Clean rebuild:
  docker-compose -f docker-compose-guardian-demo.yml down --volumes
  docker system prune -a
  docker-compose -f docker-compose-guardian-demo.yml up -d --build
